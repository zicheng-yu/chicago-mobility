# 芝加哥天气和节假日与城市出行的关系

## 范围

分析 2024 年芝加哥共享单车与出租车的实际记录量，研究天气、节假日及社区差异。单车范围为普通单车与电助力单车，排除源文件中的电动滑板车。只做日级与社区日级分析，采用简单统计与聚类。所有解释均限于观察到的关联。

## 三个核心研究问题

1. 控制月份和星期后，降水与两种出行方式的每日记录量分别有什么关系？数据：Divvy、芝加哥出租车、NOAA。
2. 联邦节假日与普通工作日的出行量和出行时段有什么差异？数据：OPM 节假日、Divvy、出租车、NOAA。联邦节假日仅作日历标记，不能代表所有人的实际休假。
3. 两种出行方式在社区上的分布有何不同，雨天差异是否一致？数据：社区边界、Divvy 坐标、出租车社区编号、NOAA。

## 数据源与独立性

| 来源 | 发布者 | 角色 | 获取形态 | 关联键 |
|---|---|---|---|---|
| Divvy 2024 全年骑行记录 | Divvy / Lyft | 主要源 | 月度 ZIP 内原始 CSV | 开始日期、起点经纬度 |
| Taxi Trips 2024 | 芝加哥市 | 主要源 | 公开 Socrata JSON API | 开始日期、上车社区编号 |
| 日天气观测 | NOAA NCEI | 辅助源 | 日气候 API | 观测日期 |
| 2024 联邦节假日 | 美国 OPM | 辅助源 | 官方网页 | 日期 |
| 社区边界 | 芝加哥市 | 辅助源 | GeoJSON | 社区编号、点落区 |

按底层记录的形成过程计数，包含单车运营、出租车监管报送、NOAA 观测、OPM 日历四类独立信源，社区边界另作地理辅助。Divvy 数据所有权归芝加哥市，但运营记录和出租车报送记录由两个系统独立形成，独立性依据为数据形成过程而非所有权。数据形态包括运营记录文件、公开 API、官方网页与地理空间多边形。

## 规模与处理

使用两个主要源的全年真实明细，记录原始字节数、记录数、下载时间和 SHA-256。ZIP 仅为传输副本，规模统计只计算解压后的原始 CSV 及 API 原始响应，不重复计算归档和衍生表。实际是否达到 2 GB、每主要源 200 MB、最大单源占比 80%，由自动检查报告决定，不预填采集结果。

按月分块读取，保留原始文件、清洗后的明细压缩文件、按日及社区日聚合后的融合表。时间统一使用芝加哥当地民用日期，出租车记录的时间由发布者取整到 15 分钟，不做分钟级比较。

## 简单分析方法

描述统计、月份和星期分组、带日历控制变量的线性回归、社区对比。使用 KMeans 对日级出租车量、温度、降水和风速做三个探索性类别，固定随机种子，汇报类别规模与轮廓，不赋予类别因果解释。结合 Divvy 数据许可，聚类不包含单车运营特征。
